# wp_pivot_flutter

Windows Phone style Pivot navigation for Flutter. `WpPivotView` provides cyclic
headers, drag tracking, release-time selection and separate outgoing/incoming
page transitions. The existing header-only `WpPivot` and `PivotController` APIs
remain available.

## Requirements

Version 2.2.0 requires Flutter **3.22.0+** and Dart **3.4.0+**.
The repository example uses Flutter 3.44+ for its current Android toolchain;
the package library retains the 3.22 minimum.

## Full Pivot example

```dart
import 'package:flutter/material.dart';
import 'package:wp_pivot_flutter/wp_pivot_flutter.dart';

void main() => runApp(MaterialApp(
  theme: ThemeData(brightness: Brightness.dark, fontFamily: wpPivotFontFamily),
  home: WpPivotView(
    title: 'MY APPLICATION',
    tabTitles: const ['first', 'second', 'third'],
    children: const [
      Center(child: Text('First page')),
      Center(child: Text('Second page')),
      Center(child: Text('Third page')),
    ],
  ),
));
```

Pass an optional `PivotController` to drive selection externally and dispose
controllers you create. `onChanged` reports committed selections. Pages retain
their state while hidden. Set `wrap: false` to stop at the first and last pages.
Give the view a bounded width and height.

Title, header and content swipes share the gesture surface. Arrow keys navigate,
headers expose semantic selection and keyboard focus, and the system's reduced
animation setting removes spatial transitions. Customize colors, font families,
weights and `PivotMotion` parameters to suit your application.

## Migrating from the header-only control

Replace the `WpPivot` app bar and external `PageView` with one `WpPivotView`.
Move your pages into `children` and remove the two-controller synchronization.
The full view owns both layout and page transitions; a stock `PageView` does not
reproduce its separate exit and entry phases.

Existing `WpPivot` and `PivotController` integrations do not need API changes.
See the [legacy example](https://github.com/Chinmay-KB/wp_pivot_flutter#legacy-header-only-example)
if you only need a header bar.

## Experimental components

Import `package:wp_pivot_flutter/wp_components.dart` to use the opt-in
Application Bar, Panorama, ToggleSwitch, Slider, ProgressBar, and TiltEffect
controls. Slider is controlled and supports pointer, keyboard, RTL, and
accessibility actions. ProgressBar supports determinate and indeterminate modes;
TiltEffect preserves its child's interaction while adding press-position motion.

The three micro controls were measured with repeated WP8.1 emulator captures and
held-out input replay. They remain experimental, and emulator evidence does not
establish Lumia hardware fidelity. The existing Pivot library is unchanged.

## Fonts and evidence

The package bundles unmodified **Selawik 1.01** under the
[SIL Open Font License](https://github.com/Chinmay-KB/wp_pivot_flutter/blob/master/assets/fonts/OFL.txt).
It does not redistribute proprietary Segoe WP fonts. Selawik and Flutter's
rasterizer differ from native Windows Phone rendering.

Motion and geometry were studied using Microsoft's native Pivot on the WP8.1
emulator. Regression tests replay 51 recorded selection traces. These are not
Lumia recordings; hardware validation remains pending. Capture timing cannot
establish physical display latency, and motion parameters remain provisional
outside the measured inputs. The separate release-web probe measures engine
timing on its recorded host, not mobile or Lumia performance.
